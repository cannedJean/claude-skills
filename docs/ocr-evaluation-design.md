# agy 이미지 분석 결과를 "이미지를 다시 보지 않고" 검증하는 설계

`agy-slide-analyzer` / `agy-pdf-analyzer`가 agy(Gemini)에 위임한 OCR·구조화 결과를, 수행자와 다른 회사의
LLM(Claude CLI)이 검수하되 이미지를 다시 분석하지 않도록 만든 평가 로직의 설계 근거와 동작을 정리한다.

## 1. 문제

| | 기존 구조 | 문제 |
|---|---|---|
| 수행 | agy 분석가 세션(슬라이드당 1회) | - |
| 검수 | agy 검수자 세션이 **이미지를 다시 보고** 판정(슬라이드당 +1회, 재시도 시 +2회) | 분석을 한 번 더 하는 비용. 쿼터(`RESOURCE_EXHAUSTED`) 두 배 소모 |
| 편향 | 수행자와 검수자가 같은 회사 모델 | 자기선호(self-preference): 같은 계열 모델은 서로의 오류를 비슷하게 놓친다 |

검수를 Claude로 옮기면 편향은 해결되지만, Claude가 이미지를 전부 다시 보면(장당 800~1,600 토큰 + 추론)
토큰 절약을 위해 agy에 위임한 의미가 사라진다. 그래서 질문은 이것이다.

> **이미지를 이해하지 않고도 "이미지를 제대로 설명했는가"를 판정할 수 있는가?**

## 2. 원칙

### 2.1 평가 기준은 작업 전에 봉인한다 (사전 등록)

이미지를 이해하지 않고도 **작업 전에** 만들 수 있는 것이 두 가지 있다.

- **독립 참조(reference)**: 로컬 OCR 엔진이 뽑은 텍스트·단어 박스·신뢰도, 잉크 밀도, 비텍스트 잉크 비율,
  괘선 수, 격자 정렬 단어(표 후보), 제목 띠, 퍼셉추얼 해시. agy를 호출하기 전에 계산해 이미지 sha256과 함께
  `ref/<stem>.json`에 저장한다. agy의 출력은 참조에 영향을 줄 수 없다.
- **고정 규칙(rubric)**: 스키마, 근거성(grounding), few-shot 누출, 임계값. 저장소에 버전 관리되고 골드셋으로
  캘리브레이션된다.

### 2.2 서로 다르게 틀리는 두 관측을 교차한다

로컬 OCR은 틀린다. 그러나 LLM과 **다른 방식으로** 틀린다.

| | 로컬 OCR | 멀티모달 LLM |
|---|---|---|
| 전형적 오류 | 폰트·노이즈로 글자 오독(`NULL`→`NULLS`, `DBMS`→`08146`), 음절 단위 분절(`테 이 블 당`), 구두점 혼동(`1,024`→`1.024`) | 문장 누락, 환각(없는 문장 추가), 조용한 "교정"(`2024`→`2023`, 오타 수정), 표를 평문으로 눌러 씀, 페이지 섞임 |
| 오류의 분포 | 단어 단위로 흩어짐 | 문장·필드 단위로 뭉침 |
| 비용 | 장당 1초 미만, 토큰 0 | 장당 수천 토큰 |

오류가 비상관이므로 **두 관측이 일치하는 부분은 신뢰**하고, **불일치하는 부분만** 제3자에게 보낸다. 이것이
"이미지를 다시 분석하지 않고 검증"의 핵심이다. 이미지 전체를 보는 대신 분쟁 지점만 본다.

### 2.3 점수가 아니라 결정을 낸다

평가의 소비자는 사람이 아니라 파이프라인이다. 0.87이라는 점수보다 "끝났다 / agy에 다시 시켜라 / Claude가 이
줄만 봐라"가 필요하다. 결정은 네 가지다.

```
accept    참조가 동의 → 종료. 검수 토큰 0
retry     명백한 누락(recall < 0.6) 또는 스키마/누출 오류 → agy 재실행. 피드백에 "OCR이 읽었는데 빠진 줄" 목록을 그대로 넣는다
escalate  텍스트로 결판나지 않는 불일치 → Claude에게 분쟁 크롭(또는 축소본)만 제시
unverified 참조를 만들 수 없고 보여줄 것도 없음 → 검증 안 됨을 명시
```
여기에 accept 중 무작위 표본(기본 10%, 최소 2장)을 Claude가 블라인드로 읽는 **감사(audit)** 를 더해 전체
실행의 잔여 오류율을 추정한다.

### 2.4 Claude의 검수는 블라인드 크롭 판독이다

- 스크립트가 **불일치한 OCR 줄의 박스 영역만 크롭**해 저장하고 `review_queue.md`에 크롭 ID만 나열한다.
  agy의 전사문도, OCR의 텍스트도 보여주지 않는다.
- Claude는 크롭을 보고 읽은 글자를 `crop_reads.json`에 적는다. 스크립트가 agy 값과 대조한다(숫자·식별자는
  정확 일치 필수). 검수자가 수행자의 답을 먼저 보지 않으므로 앵커링도 자기선호도 없다.
- 구조 질문(표/도식 미선언)과 감사 표본은 640px 축소본으로 처리한다. 감사는 "읽을 수 있는 줄을 적어라"는
  블라인드 질문이고, 스크립트가 (1) Claude가 읽은 줄이 분석에 있는지(누락), (2) OCR도 Claude도 못 본 분석
  문장이 있는지(환각)를 계산한다. 후자는 Claude가 OCR 고신뢰 줄(high·variant 단어 2개 이상, 그런 줄이 없으면
  mid 단어까지 쳐서 2개 이상인 줄)의 70% 이상을 읽어낸 경우에만 판정한다(축소본이 너무 작아 못 읽은 것과
  구분하기 위해). 축소본 읽기에도 숫자·식별자 정확 일치 검사가 붙는다.

## 3. 메트릭

정규화: NFKC → 소문자 → 공백·구두점 제거. 한국어 OCR이 음절 단위로 끊기므로 단어 경계를 쓰지 않고 **문자
바이그램 집합 겹침**(기본 0.75)으로 매칭한다. 이 정규화(`textnorm.norm`)는 연산자도 지우므로(`age > 30`과
`age < 30`이 같아진다) 연산자·숫자·줄 순서는 별도의 줄 단위 검사가 맡는다(9절). OCR 형태 혼동(`I`/`l`/`1`/`|`,
`O`/`0`, 각종 대시, 둥근 따옴표)은 `norm`에 넣지 않고 별도 키(`fold`, `ocr_key`, `skel`)로만 비교한다. `norm`을
바꾸면 lecture-knowledge-pack의 개념 레지스트리 키가 바뀌기 때문이다.

| 실패 유형 | 메트릭 | 정의 |
|---|---|---|
| 누락 | `recall` | 참조 단어(가중치 high=1, mid=0.5, low=0) 중 분석 코퍼스에서 찾은 비율 |
| 환각 | `unsupported_ratio` | 분석 전사 텍스트(title/verbatim/tables/code) 중 참조에 없는 글자 비율. 도식 요소는 설명일 수 있어 제외 |
| 환각(문장 단위) | `unsupported_fields` | 10자 이상이면서 70% 이상 확인되지 않는 verbatim 항목. OCR 노이즈는 흩어지고 환각은 뭉친다는 점을 이용 |
| 숫자 교정 | `digit_recall` | 참조 high·variant 단어의 숫자열(구분자 제거: `1,024`=`1.024`=`1024`) 중 분석에 있는 비율. 빠진 숫자의 줄은 크롭 큐로. 영문 글자 **뒤에** 붙은 숫자(`He110`, `tit1e`)는 숫자가 아니라 글자 문제로 보고, 단위가 뒤에 붙은 숫자(`1200px`, `500ms`)는 검사한다 |
| 식별자 교정 | `latin_recall` | 참조 high·variant 단어의 영문 식별자(코드·약어) 중 분석에 있는 비율. 둘 다 없으면 mid 단어의 식별자도 형태 혼동을 접어 검사(`latin_mid`) |
| 연산자·숫자·순서 | `line_issues` → `operator_or_digit_mismatch`, `line_order_mismatch` | OCR 줄마다 가장 잘 포함되는 분석 줄(골격 포함률 ≥ 0.7, 토큰 50% 이상 겹침; 토큰이 숫자 1–2개뿐인 줄은 나머지 글자가 같으면 맞춘다)을 찾아 비교 연산자(`=== !== == != <= >= => && \|\| < > %`)와 독립 숫자가 하나 대 하나로 다르면 분쟁. 줄 대응은 가능한 한 일대일이라 슬라이드에 두 번 나오는 줄은 분석의 두 사본과 각각 비교한다. 같은 코드 패널 안 OCR 줄이 분석의 코드에서 역순이면 순서 분쟁(코드가 `verbatim_text`에도 복사되어 있어도 코드 쪽으로 잰다) |
| 한쪽만 고친 사본 | `copy_issues` → `copy_mismatch` | 다른 필드에 두 번 적힌 같은 줄(코드와 본문, 제목과 본문)의 연산자·숫자 열이 다름 |
| 표 평문화 | `table_candidate_undeclared` | 격자 정렬 단어 또는 괘선 표가 있는데 `tables`가 비고 3줄 이상 코드도 없음. layout v3는 코드 패널을 지운 뒤 머리글·꼬리글 띠를 빼고 가까운 단어를 셀로 묶은 `table_grid2`(셀의 시작·끝·가운데 중 하나가 3셀 이상 맞으면 열: 왼쪽 정렬 글자, 오른쪽 정렬·가운데 정렬 숫자)와 칸마다 글자가 있는 `ruled_table2`를 쓴다. 단어 상자가 없는 PDF 텍스트 레이어 페이지(`text_masked: false`)는 v2 키(`table_candidate`, `ruled_table`)로 판단한다 |
| 도식 무시 | `graphics_undeclared` | layout v3: 어두운 코드 패널을 지운 비텍스트 잉크 비율(`graphics_ratio_nocode`) ≥ 1.5%인데 `diagrams`가 빔. 어두운 영역은 OCR 단어 상자가 그 안의 밝은 잉크를 70% 이상 덮을 때만 코드 패널이고(어두운 테마의 구성도는 그래픽), 패널 위에 그린 표시(강조 상자, 화살표)는 그래픽으로 센다. 단어 마스크가 없는 PDF 텍스트 레이어 페이지(`text_masked: false`)에서는 판단하지 않는다. 구버전 참조는 원래 규칙(텍스트 박스 밖 잉크 ≥ 6%) |
| 참조 부실 | `ref_thin`, `ref_unreliable`, `agy_rich_ref_empty` | 가중 단어 < 5, 평균 신뢰도 < 55, 참조는 비었는데 분석은 풍부 |
| 해석 과장 | grounding(기존 검증기) + 텍스트 전용 큐 | summary/key_concepts/exam_points가 전사문에서 도출되는지 Claude가 **텍스트만으로** 판정 |

단어 가중치: Tesseract 신뢰도 ≥80 → high, ≥60 → mid, 미만 → low. Windows OCR은 신뢰도가 없으므로 mid.
두 엔진이 모두 읽은 단어는 high. 즉 두 엔진을 함께 쓰면 Windows OCR의 신뢰도 부재를 교차 일치로 보완한다.
엔진이 하나뿐이면 같은 엔진을 2배 업스케일로 한 번 더 돌리고(`winocr_x2`), 두 패스가 형태 혼동을 접은 키로
**정확히** 같게 읽은 단어를 `variant`(가중치 1.0)로 둔다. 같은 인식기의 두 번 읽기는 오독도 공유하므로
`high`라고 부르지 않는다(lecture-knowledge-pack은 `high`만 "숫자 검사됨"으로 친다). 숫자·식별자 검사는
high와 variant 단어에서 한다.

덱 템플릿: 5장 이상의 참조에서 같은 위치(50×50 격자의 중심)에 같은 텍스트(공백을 빼고 `I`/`l`만 접음; 연산자와
숫자는 그대로)로 나오는 OCR 줄 중 **머리글 띠(위 20%)나 꼬리글 띠(아래 12%)에 있고 코드 패널 밖인 줄**(로고,
과정명 띠, 꼬리글)은 recall과 누락 줄에서 뺀다. 본문 자리의 반복은 내용이다: 한 단계씩 진행하는 코드 설명은
같은 코드를 같은 자리에 여러 장 싣는다. 분석 쪽의 `header/footer`·`page_number` 항목과 중복 제목은 "풍부한
분석" 길이(`content_chars`)에서만 빼고, 환각 검사(unsupported)에는 다른 글자처럼 들어간다: 그 표시는 분석가
자신이 붙인 것이다. 예외는 덱의 상투 문구 하나다: 3장 이상의 분석에서 `header/footer`·`page_number` 항목에 나오는
단위(로고, 슬로건, 단원 띠; `ocr_score.hf_boilerplate`)는 그런 항목 안에서만 unsupported 비율과 필드 검사에서
빠진다(recall에는 그대로 쓰인다). 다른 필드의 단위는 세지 않으므로 덱 전체에 흔한 본문 용어는 상투 문구가 되지
않고, 그 표시를 붙여 지어낸 문장의 나머지 단위는 여전히 검사된다(9.6). 템플릿 키는 선택 범위가 아니라 디스크의 모든
참조로, 상투 문구는 디스크에 있는 이 덱(슬라이드 폴더의 stem; PDF는 그 쪽수까지)의 모든 분석으로 만들므로 `run`은
분석 전에 덱 전체의 참조를 먼저 봉인하고, 분석가 풀이 끝나면 판정이 없는 덱의 모든 슬라이드를 덱 전체 기준으로 다시
채점한다(settle).

결정 규칙(기본 임계값, `calibration.json`으로 대체 가능):

```
validator error                                  → retry
text-layer 참조 & 연산자·숫자 줄 분쟁           → retry (참조가 정확하므로; 재시도도 다르면 needs_attention)
ref thin  & recall ≥ 0.90 & unsupported ≤ 0.15 & unsupported_fields = 0
          & digit ≥ 0.90 & latin ≥ 0.85
          & 풍부한 분석이면 도식 요소까지 넣은 unsupported ≤ 0.15
          & 줄 분쟁·구조 트리거 없음              → accept  ("little text on both sides", "thin reference, content supported")
ref thin  & 위 조건 중 하나라도 어긋남            → escalate ("thin reference, content not confirmed"; thumbnail, 줄 분쟁이면 crops도)
recall < 0.60                                    → retry
recall ≥ 0.90 & unsupported ≤ 0.15 & unsupported_fields = 0
  & digit ≥ 0.90 & latin ≥ 0.85 & 줄 분쟁·구조 트리거 없음  → accept
그 외                                            → escalate (분쟁 줄에 박스가 있으면 crops, 구조·환각 의심이면 thumbnail)
```
예전에는 참조가 얇으면(가중 단어 < 5) 분석이 40자 미만일 때 아무 검사 없이 accept했다. 머리글·꼬리글을 빼자 얇은
슬라이드가 크게 늘어 이 지름길이 무검사 통로가 되었기 때문에(9절), 얇은 참조도 분석 내용이 참조에 있는지는
확인한다. 첫 reason 문자열은 lecture-knowledge-pack이 `thin_accepted`를 판단하는 키라 그대로 둔다.
`unsupported`는 참조 평균 신뢰도가 55 미만이면 판단에 쓰지 않는다(OCR이 못 읽은 것을 agy 환각으로 몰지 않기 위해).

## 4. 토큰 비용 모델

| 자료 | 크기 | 대략 토큰 |
|---|---|---|
| 한 줄 크롭 | ≈ 800×60 px | ≈ 70 |
| 축소본 | 640×360 px | ≈ 300 |
| 원본 슬라이드 전체 | 1280×720 ~ 1920×1080 | 800 ~ 1,600 + 긴 추론 |

슬라이드의 20%가 에스컬레이션되고 10%가 감사된다고 하면 100장 덱의 Claude 이미지 토큰은 대략
20×(2~4 크롭 또는 축소본 1) + 10×300 ≈ 6k~9k. 전체를 다시 보는 방식(100×1,200 + 추론)의 약 1/10이다.
agy 세션은 슬라이드당 1회(재시도 시 2회)로, 기존 2~4회의 절반 이하다. `report.md`가 실제 큐의 픽셀 합으로
추정 토큰을 표시한다.

## 5. 골드셋: 게이트 캘리브레이션과 벤치마크를 한 번에

사용자가 결과 JSON 10~30장을 교정해 `gold/<stem>.json`으로 저장하면,

- `calibrate`: 골드 대비 **진짜** recall/정밀도와 OCR 기반 **대리** 지표를 함께 계산하고, false-accept(진짜
  recall 또는 정밀도 < 0.9인 슬라이드를 accept한 비율) ≤ 목표(5%)인 조합 중 가장 많이 accept하는
  `recall_accept`/`unsupported_accept`를 격자 탐색으로 고른다(동률이면 더 엄격한 쪽). 엔진별로 "골드 텍스트
  중 그 엔진이 읽은 비율"도 보고해 엔진 선택 근거를 준다. 결과는 `calibration.json`에 쓰이고 이후 실행이
  자동으로 읽는다.
- `bench`: 임의 실행의 진짜 recall/정밀도/문자 유사도/숫자·셀 정확도/환각률을 `bench.json`에 누적해 프롬프트·
  모델 버전을 비교한다.

10장 미만이면 경고가 붙는다. 골드셋 없이도 기본 임계값으로 동작하지만 그때의 임계값은 경험치다.

## 6. 파이프라인

```
덱 전체 ──> [0] ocr_ref.load_or_build  (첫 agy 호출 전, 모든 슬라이드) ──> ref/<stem>.json
            ocr_score.template_keys(디스크의 모든 참조) ──> tkeys (덱 템플릿 줄)
slide.png ──> [1] agy analyst ──> slide_analysis.json
[2] slide_validate.validate_analysis (스키마/근거성/누출/프롬프트 규칙 경고)
[3] ocr_score.score(analysis, ref, thresholds, validator_errors, tkeys, boilerplate) ──> decision
      boilerplate = hf_boilerplate(그 순간 디스크에 있는 분석 + 이 분석), score_legacy = 모든 스위치를 끈 결정
      retry    → feedback_text(): 빠진 줄·숫자·확인 안 된 조각을 한국어로 → analyst 재실행(1회)
      escalate → crops.prepare(): 분쟁 줄 크롭 / 축소본 → results/<stem>.json의 queue
[3'] settle: 분석가 풀이 끝난 뒤 판정 없는 덱의 모든 슬라이드를 덱 전체의 템플릿 키·hf_boilerplate로 다시 채점
      (agy 없음; 점수가 바뀌면 큐를 새로 만들고 기존 답은 오래된 답으로 기록, 새로 retry가 나오면 저장된 기록 유지)
[4] build_report: 감사 표본 선택(stem 해시로 결정적; 섀도 층 = 새 규칙만 accept한 슬라이드의 30%)
      → review_queue.md / grounding_queue.md / report.md
[5] Claude: 큐만 열어 crop_reads.json 작성 → resolve → crops.judge() → accepted | needs_attention
```
큐 항목마다 Claude에게 보여 준 것(PNG, thumb_struct는 분석가 선언까지)의 지문(`fp`)을 저장하고 review_queue.md에도
보인다. `run`(다시 분석하는 슬라이드)과 `rescore`는 기록을 바꾸기 **전에** 디스크에 있는 그 슬라이드의 답마다 "이전
항목(그 지문, 없으면 `before-rerun`)에 쓴 답"이라고 `applied_reads.json`에 적어 둔다. 그래서 같은 id에 이전 답이
남아 있어도 지문이 다르면 적용하지 않고(중간에 끊긴 rescore도 마찬가지), 같은 크롭이면 그대로 쓴다. 무시된 항목은
`{"answer": ..., "fp": "<fp>"}`로 다시 답한다(같은 평문 답은 계속 무시된다). `queue --shards N`은 큐를 서로 겹치지
않는 파일로 나누고, `resolve`는 `crop_reads_<k>.json`을 합치되, 오래된 답을 뺀 뒤에도 같은 id에 다른 답이 남으면
멈춘다. 줄 순서 분쟁의 크롭들은 모두 답이 온 뒤 함께 판정한다: Claude가 각 크롭을 맞게 읽어도 그 읽기들이
분석에서 슬라이드와 다른 순서로 대응하면 `agy_wrong`이다.
PDF 변형은 페이지에 텍스트 레이어가 있으면 그것을 **최고 신뢰 참조**로(`primary: pdf_text`), 없으면 pypdf로
내장 페이지 이미지를 꺼내(실패 시 pymupdf 렌더) 같은 OCR 참조를 만든다. 둘 다 안 되면 `unverified`.
report/resolve/calibrate/bench는 `slide_analyze.py`의 코드를 그대로 재사용한다(페이지 이미지를 `ref/page_XXXX.png`
라는 "슬라이드"로 취급).

## 7.1 실제 슬라이드 파일럿 (SVM 강의 3장, agy gemini-3.8-flash-high, Windows OCR + Tesseract)

첫 실행은 3장 모두 escalate(큐 14건, ≈1,165토큰)였다. 원인은 전부 **참조 쪽 잡음**이었고, 아래 네 가지를 고친
뒤 `rescore`(agy 재호출 없이 재채점)하자 2장 accept, 1장 escalate(크롭 2건)로 줄었다. Claude의 블라인드
판독과 감사 2장 결과 3장 모두 accepted, 큐 4건 ≈654토큰. agy 세션은 4회(슬라이드 3 첫 시도에서 agy가 셸
명령을 시도하다 파일을 못 써 재시도).

| 잡음 | 증상 | 조치 |
|---|---|---|
| 불릿 점·산점도 점을 `0`/`5`로 읽음 | 숫자 분쟁 → 불필요한 크롭 | 1글자 OCR "단어"는 가중치 low, 숫자 검사는 2자리 이상만 |
| `초평면(Hyperplane)`을 `초평면대yperplane`으로 붙여 읽음 | 식별자 누락 | 식별자는 포함 관계(4자 이상)도 일치로 인정 |
| 불릿 목록의 정렬을 표 후보로 오인 | 모든 텍스트 슬라이드가 `table_candidate_undeclared` | 짧은 행(2~6단어)이고 단어 대부분이 공유 열 위에 있을 때만 표 후보 |
| 상단 배너 장식이 비텍스트 잉크로 집계 | 순수 텍스트 슬라이드도 `graphics_undeclared` | 상단 13%·하단 7% 띠는 그래픽 통계에서 제외 |

남은 크롭 2건은 Windows OCR이 도식의 `y_i = +1` 기호를 `사도 BF시`로, `Hyperplane`을 `Hyverplane`으로 읽은
것이었다. 둘 다 Claude가 70토큰짜리 크롭을 읽어 agy가 맞았음을 확인했다. 단일 엔진의 오독이 크롭으로
흡수되는 설계대로다.

## 8. 한계와 열어 둔 것

- **OCR이 못 보는 것**: 도식의 관계(화살표 방향, 카디널리티), 색·강조, 레이아웃 의미. 축소본 질문과 감사
  표본으로만 다루며, 도식 정확도 자체는 측정하지 않는다. 도식이 중요한 덱이라면 `--audit-rate`를 올리거나
  해당 슬라이드만 `--force`로 agy에 재분석을 시키는 것이 낫다.
- **표 격자/비텍스트 감지는 휴리스틱**이다. 자동 reject의 근거로 쓰지 않고 축소본 질문으로만 쓴다.
- **단일 엔진**: 업스케일 변형 패스가 숫자·식별자 검사를 되살리지만 같은 인식기의 오독은 공유한다. 서로 다른
  두 엔진(Tesseract `kor` + Windows OCR)이 여전히 더 낫다.
- **연산자 검사의 사각**: `==`→`=`, `+`→`-`, `*`→`/`, `++`→`--`, `!` 누락, 단위에 붙은 숫자(`50px`→`5px`)는
  잡지 못한다. OCR이 대시·글머리표를 `- = + !`로 읽기 때문에 이것들은 결정 근거로 쓰지 않는다.
- **블라인드의 한계**: 구조 질문(`thumb_struct`)은 분석가의 선언을 보여줘야 비교가 가능하므로 블라인드가
  아니다. 닫힌 질문으로 제한했다.
- **임계값은 자료 종류마다 다르다**. 손글씨·저해상도 스캔은 OCR 신뢰도가 낮아 `ref_unreliable`이 자주 켜지고
  escalate가 늘어난다. 그런 자료는 골드셋 캘리브레이션 없이는 수치 게이트를 믿지 말 것.
- 기존 agy 검수자 모드는 `--reviewer agy`로 남겨 두었다. 같은 덱을 두 모드로 돌려 `bench`로 비교하면 이
  설계의 효과를 수치로 확인할 수 있다.

## 9. 2차 개선: 123장 실제 덱에서 측정 (REF_VERSION 3, scorer v2)

HTML/JavaScript 코드가 어두운 패널에 많이 실린 실제 강의 덱 123장(Windows OCR 한 엔진)을 1차 설계로 돌린 결과를
agy 재호출 없이 다시 채점해 원인을 쪼개고, 고친 뒤 같은 저장분으로 다시 쟀다. 슬라이드 내용은 저장소에 넣지 않았고
테스트 픽스처는 모두 합성이다.

### 9.1 검수 부담은 어디서 왔나

| | 1차 설계 |
|---|---|
| 첫 결정 | accept 22 / escalate 101 |
| 리뷰 큐 | 159건(line 58, thumb_struct 57, thumb_read 41, thumb_audit 3), 이미지 토큰 ≈32.6k |
| 실제 리뷰 비용 | 서브에이전트 4개, 322,948토큰 ≈ 항목당 2,030토큰(이미지 토큰의 약 10배: 에이전트 컨텍스트 전체) |
| 리뷰 뒤 | accepted 118, needs_attention 5. 에스컬레이션 정밀도 5/101 |
| 에스컬레이션 원인(배타 분할) | 얇은 참조 29, 그래픽 39, 그래픽 없는 표 18, 텍스트만 15 |

가설 검증:

| 의심 | 결과 |
|---|---|
| 어두운 코드 상자는 OCR이 못 읽는다 | **반박.** 코드 커버리지 97.3%, 반전해도 97.4%, 결정 변화 0 |
| `graphics_undeclared`가 코드 상자에 반응한다 | **확인.** 39건 중 37건 오탐 |
| 표 후보가 코드 상자 때문이다 | **대부분 반박.** 21건 모두 오탐이지만 원인은 산문·목차 격자와 메모 테두리 |
| 엔진 하나면 숫자·식별자 검사가 없다 | **확인.** 123장 중 0장 검사 |
| 정규화가 연산자를 지운다 / 바이그램은 순서를 모른다 | **확인.** 코드 줄 순서 바꾸기 110건 중 0건 탐지 |
| 얇은 참조 accept는 아무것도 검사하지 않는다 | **확인.** 머리글·꼬리글을 빼면 31장이 그 통로로 간다 |
| cp949 콘솔에서 출력이 죽는다 | **확인(좁게).** cp949로 못 쓰는 문자(– — • ≈)가 경로에 있을 때만 |
| `--pages` 보고서가 덱 파일을 덮어쓴다 | **확인.** 감사 표본까지 선택 범위로 줄어든다 |

### 9.2 바뀐 것

- **참조(REF_VERSION 3)**: 어두운 코드 패널 검출(6px 블록, 휘도 < 50, 폭 ≥ 페이지의 12%, 높이 ≥ 24px, 어두운
  화소 ≥ 55%, 표준편차 ≤ 12, 여백 없음; OCR 단어가 테두리 8px을 뺀 밝은 잉크의 70% 이상을 덮어야 함)로 패널을
  지운 `graphics_ratio_nocode`(패널 위 표시는 남김); 표 검출 재작성(`table_grid2`,
  `ruled_table2`); 단일 엔진이면 2배 업스케일 변형 패스와 `variant` 가중치; Windows OCR의 최대 이미지 크기를
  클래스 속성에서 읽도록 수정(모든 이미지가 2,600px로 잘리던 버그). 기존 키(`graphics_ratio` 등)의 의미는 그대로.
- **채점(scorer v2)**: 형태 혼동 폴백, 덱 템플릿 줄과 머리글·꼬리글 제외, 얇은 참조 지름길 닫기, 줄 단위
  연산자·숫자·순서 검사, 이중 기재 일치 검사, mid 단어 식별자 검사, 글자에 붙은 숫자 건너뛰기. 각 부분은
  `DEFAULT_THRESHOLDS`의 스위치(`fold_match`, `template_exclusion`, `close_thin_shortcut`, `line_check`,
  `copy_check`, `latin_mid`, `glued_digit_skip`, `table_v2`, `graphics_trigger_nocode`)로 끌 수 있어
  하나씩 빼며 효과를 잴 수 있다. 출력은 추가만 했다(`line_issues`, `copy_issues`, `metrics.content_chars`,
  `metrics.template_lines`).
- **판정(crops.judge)**: 축소본 전체 읽기도 줄 크롭처럼 숫자(2자리 이상)·식별자(3자 이상) 정확 일치를 본다.
  1차에서는 `2024`→`2023`을 바꾼 분석이 축소본 읽기로 accepted가 될 수 있었다. 줄 크롭은 연산자도 비교한다.
  환각 의심 단위에서 덱 상용구(3장 이상의 분석에 나오는 단위)와 둥근 따옴표를 뺀다.
- **보고서와 감사**: 덱 파일은 항상 모든 결과로 만들고 `--pages`는 반환 개수(종료 코드)만 좁힌다. 감사는 OCR로
  accept된(Claude 판정이 없는) 슬라이드에서만 해시로 뽑아 별도 항목(`<stem>__thumb_audit`)으로 묻고, 보고서는
  "OCR-accepted(독립 감사)"와 "Claude-accepted(감사 아님)" 두 층을 따로 쓴다. accepted가 50장 이상이면 최소
  10장, 상한은 30% 미만일 때만 표시한다.
- **견고성**: UTF-8 stdout과 출력 전 종료 코드 결정, 원자적 쓰기, 읽을 수 없는 결과는 다시 처리, 재시도 중
  쿼터 소진 시 첫 분석 보존, 덱 매니페스트(`slides_source.json`; `source.json`은 PDF 표식이라 쓰지 않음)와
  다른 덱의 `--out` 거부(종료 코드 5), 판정이 붙은 슬라이드의 참조는 `rescore`와 `--force`만 다시 만든다(줄 id가 바뀌므로).
- **프롬프트와 검증기**: 화면 캡처는 `screenshot`, 강조 표시는 `annotation`, 이름표 붙은 코드 분해는
  `syntax_breakdown` 도식으로 선언하고, 코드·표·도식에 옮긴 글자는 `verbatim_text`에 다시 쓰지 않으며, 제목만
  있는 슬라이드는 exam_points를 비운다. 검증기 경고 `interpretation_on_title_only`(텍스트 전용 근거성 큐로),
  `visual_undeclared`, `code_duplicated`, `illustration_with_relations`, `divider_with_body`, 정보
  `series_type_mixed`. PDF 쪽 프롬프트·검증기도 같은 규칙과 열거형을 쓴다.

### 9.4 하지 않은 것과 주의

- `norm`·`PUNCT_RE`·`units`·`bigrams`·`fuzzy_in` 등 정규화 함수는 바이트 단위로 그대로 둔다(형태 혼동을 `norm`에
  넣으면 accept가 4/123로 무너지고 kp의 개념 키가 바뀐다). 계약은 `scripts/tests/test_contract.py`가 고정한다.
- 어두운 상자 반전(+0.1%p, 결정 변화 0), "코드 블록이 그래픽을 설명한다" 예외(검증된 문제 2건을 조용히 accept),
  mid 단어에 대한 집합 기반 숫자 검사(OCR 잡음으로 오탐), 줄 검사의 식별자 치환(21–23장 오탐), 기본 3배 패스,
  업스케일 패스로 기본 패스 대체(큰 글자 정밀도 −6.7%p)는 넣지 않았다. 변형 일치를 `high`로 부르지 않는다.
- 임계값과 템플릿 규칙은 **이 덱 하나, 엔진 하나**로 맞췄다. 코드 없는 그래픽 임계값 1.5%는 여유가 작다(실제
  문제 0.0165, 다음 오탐 0.0142). 다음 두 덱은 새 규칙만 accept한 슬라이드의 30%를 감사해 표본 밖 잔여 오류를
  재야 한다(섀도 모드, 9.6). 골드셋 없이 recall·unsupported·숫자·식별자 임계값은 바꾸지 않았다.
- 프롬프트 변경의 효과(캡처 라벨 누락, 제목만 있는 슬라이드의 지어낸 시험 포인트)는 경고 개수만 쟀다. 실제
  개선은 agy 재실행이 있어야 확인된다.
- REF_VERSION 3이나 다른 엔진 구성(변형 패스 이전)의 참조는 그 슬라이드를 다시 분석할 때, `reference`, `rescore`가
  다시 만든다(OCR만, 슬라이드당 약 0.15초, 변형 패스 포함 약 0.5초). 끝난 덱에 `run`만 다시 돌리면 참조는 그대로다.
  판정이나 대기 중인 줄 크롭이 있는 슬라이드의 참조는 `run`과 `reference`가 건드리지 않는다(그 id가 참조의 줄
  id를 가리키므로); `reference`는 만든/유지한/그대로 둔 개수를 따로 보고한다. 저장된 calibration.json은 없었다.
  이후 `calibrate`는 `scorer_version`을 기록하고, 옛 채점기로 맞춘 파일에는 경고를 낸다.

### 9.5 2차 리뷰에서 막은 통로

리뷰가 합성 슬라이드로 재현한 잘못된 accept와 오래된 답의 재사용을 근본에서 고쳤다. 각각
`scripts/tests/test_regressions.py`(PDF는 agy-pdf-analyzer의 `test_pdf.py`)에 회귀 테스트가 있고, 저장분 재채점
결과(100/23, 리뷰가 문제를 찾은 5장은 모두 escalate)는 그대로였고, 저장된 Claude 답 178건(줄 66, 축소본 읽기 50,
구조 62)을 새 판정기로 다시 판정해도 판정이 같았다.

- 덱 템플릿을 머리글·꼬리글 띠로 한정: 6단계 코드 설명에서 코드 블록을 통째로 빼도 accept되던 문제.
- 얇은 참조 지름길에 숫자·식별자 검사와 도식 요소 확인을 넣음: 상자만 있는 슬라이드에 지어낸 ERD, `1000`→`10000`.
- `header/footer`·`page_number` 표시 항목도 환각 검사: 그 표시만 붙이면 지어낸 문장이 통과하던 문제(100/100).
- 어두운 영역은 OCR 글자가 밝은 잉크를 덮을 때만 코드 패널: 어두운 테마 구성도, 패널 위 강조 표시.
- `table_grid2`가 오른쪽·가운데 정렬 열도 인식; 텍스트 레이어 PDF 페이지는 v2 표 키 사용.
- 숫자 뒤에 단위가 붙은 경우(`1200px`)는 숫자 검사; 숫자 하나뿐인 한국어 줄도 줄 검사; 슬라이드에 두 번 나오는
  줄은 두 사본 모두와 비교; 코드가 `verbatim_text`에도 있어도 순서 검사.
- 텍스트 레이어 참조와 연산자·숫자가 다르면 retry(축소본 읽기가 덮어쓰지 못함).
- 판정: 축소본 전체 읽기도 줄마다 연산자·숫자를 모든 사본과 비교; 줄 크롭은 채점기가 비교한 분석 줄과도 비교;
  순서 분쟁 크롭은 함께 판정.
- 답 장부: `run`·`rescore`가 기록을 바꾸기 전에 기존 답을 이전 항목의 것으로 기록(중간에 끊겨도); 오래된 답은
  충돌 검사에서 빠지고, `{"answer", "fp"}` 형식으로 다시 답할 수 있게 review_queue.md에 `fp`를 보임.
- `reference`가 대기 중인 줄 크롭이 있는 슬라이드의 참조를 다시 만들지 않음(줄 id 보존); PDF 페이지 이미지는
  원자적으로 저장하고 손상되면 다시 꺼냄.

### 9.6 3차: 덱 상투 문구, settle, 섀도 모드

출하 코드 측정에서 두 게이트가 떨어졌다. 코드 줄 넣기 변조가 accept된 98장 중 14장만 뒤집었고(14.3%, 시제품
25.0%), 2배 패스를 끈 `OCR_SCALES=1`에서는 accept가 76장이었다(계획 96–97). 원인은 하나였다. 9.5에서
`header/footer` 표시 항목을 환각 검사에 넣으면서, OCR이 못 읽는 로고·슬로건 단위(각각 20장 안팎의 꼬리글 항목)가
unsupported에 들어갔다. 변형 참조에서는 이 단위들이 분모를 키워 끼워 넣은 코드 줄의 비율을 0.128–0.148로 묽혔고,
단일 패스 참조에서는 얇은 참조 슬라이드 21장을 에스컬레이션시켰다.

- **덱 상투 문구** (`hf_boilerplate`, 스위치 `hf_boilerplate`): 3장 이상의 **서로 다른** 분석에서
  `header/footer`·`page_number` 항목에 나오는 단위만 센다. 그런 항목 안의 이 단위들은 unsupported 비율과
  `unsupported_fields`의 분자·분모 모두에서 빠지고 `unsupported_units`에도 나오지 않는다. 대신
  `metrics.boilerplate_chars`에 그 글자 수가 남는다. 같은 항목의 나머지 단위와 다른 필드에 쓴 같은 단어는 전처럼
  검사한다. 그래서 9.5의 통로(지어낸 문장에 `header/footer` 표시)는 닫힌 채다. 축소본 판정(`crops.prepare`/`judge`)의
  상투 문구는 전처럼 모든 필드 기준(`deck_boilerplate`)이다.
- **settle**: `run`의 분석은 병렬로 도착하므로, 첫 결정은 그 순간 디스크에 있는 분석(과 자기 자신)의 상투 문구로
  낸다. 분석가 풀이 끝나면(보고서와 큐를 만들기 전에) 점수가 있고 아직 판정이 없는 덱의 **모든** 기록을, 디스크에
  있는 이 덱의 모든 결과로 다시 만든 상투 문구와 템플릿 키로 재채점한다(저장된 검증기 결과, agy 호출 없음). 이번 run이
  분석한 슬라이드만이 아닌 것은, 할당량으로 멈춘 뒤 다시 실행하거나 `--force --pages`로 일부만 다시 분석해도 나머지
  슬라이드의 상투 문구가 바뀌기 때문이다. 점수(결정, 이유, needs, 지표)가 바뀌면 결정이 같아도 `decide()`를 다시
  돌리고(이전 크롭·큐 항목은 버리고 그 답은 장부에 오래된 답으로 기록; 장부에 같은 답이 이미 있으면 그 기록을 유지),
  로그에 `settle:` 줄을 남긴다. 저장된 결정이 retry가 아닌데 재채점 결과가 retry이면 agy를 부를 수 없으므로 저장된
  기록을 유지하고 로그에 적는다. 같은 분석·참조에 대해 `run`과 `rescore`의 결정·이유·큐가 같다. 상투 문구와 settle은
  슬라이드 폴더의 stem(PDF는 1..쪽수)만 읽는다: 같은 `--out`에 남은 더 긴 덱의 결과는 세지 않는다.
  agy-pdf-analyzer의 `run`도 같은 함수(`settle`)를 쓴다.
- **알려진 한계**: 같은 지어낸 문장을 분석가가 3장 이상에서 `header/footer`로 표시하고 OCR이 한 번도 읽지 못하면,
  글자만 보는 채점기에게 그것은 OCR이 못 읽는 로고와 구별되지 않아 상투 문구가 된다(규칙의 정의 그대로). 두 장이거나
  다른 필드에 쓰면 여전히 검사된다. 덱 비율 기준 max(3, ⌈0.1·n⌉)은 Vue 덱에서 accept를 하나도 잃지 않지만(두 구성
  모두; 빠지는 단위는 conditional·참고뿐), 30장 미만 덱에서는 그대로 3장이고 단원 띠(13–18장)는 여전히 상투 문구로
  남아 규칙(min_slides=3)을 바꾸지 않았다. kp는 `header/footer` 항목을 강의 내용에서 빼므로(META_REGIONS) 영향은 메타데이터에 그친다.
- **섀도 모드** (롤아웃 게이트 3): 채점한 모든 기록에 `score_legacy`(`{decision, reasons}`, 새 스위치를 모두 끈
  1차 규칙의 결정; 상태 결정에는 쓰지 않는다)를 추가로 적는다(run, settle, rescore; 슬라이드와 PDF). 감사 선택에
  두 번째 층을 더했다: 새 규칙은 accept했지만 `score_legacy`는 accept하지 않은 슬라이드("새 규칙만 accept") 중
  stem 해시로 `--shadow-audit-rate`(기본 0.3, 0이면 끔)만큼 같은 `<stem>__thumb_audit` 항목을 받는다(기록에
  `audit_stratum: new_only`, 기존 층은 `ocr`). 한 슬라이드는 한 번만 감사하고, 기존 층의 최소 표본 규칙과 추정치는
  그 층의 감사만으로 계산한다. report.md는 `Audit (new-rule-only accepts): audited N of M accepted, K with issues →
  estimated residual error X% …` 줄과 새 규칙 대 1차 규칙의 accept 수 줄을 따로 쓴다. 다음 덱들에서 이 층을 감사하고,
  두 덱에서 문제가 없으면 `--shadow-audit-rate 0`으로 끈다(`score_legacy`는 계속 적히고 리뷰 토큰은 들지 않는다).
